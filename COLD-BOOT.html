Cold
Boot

The machine has to be alive before you are any use to it. Here is how it wakes up.

Before you touch anything, someone has to turn this thing into a computer.

Right now it is a browser with delusions. Google shipped you a real Linux machine and then hid it, the way you hide a lighter from a toddler. We are going to un-hide it. Then we are going to put nine professional tools inside it and pull down twelve programs written specifically to keep you out.

Most of this is plumbing, and plumbing is your dad's problem: the parts that want a grown-up's password. Your one job on this page comes first, and it takes ten seconds. Sign in.

Then you watch the rest closely, because a reverse engineer who does not understand his own machine is just a person typing hopefully at a screen. I have met that person. I built a supercomputer partly so I would never have to be him.

Five steps. The first is yours. The middle three are plumbing. The fifth is where I hand you the keys and stop talking.

STEP 01  /  YouSign in

This one is yours, and it comes first. The moment the Chromebook is on, sign in. Nothing else on this page works until you do.

  1. Power on, connect to your Wi-Fi.
  2. Sign in with your Google account.
  3. Get to the desktop. That is the whole step. The interesting part comes next.

STEP 02  /  HandlerTurn on the second computer

This Chromebook is two machines wearing one case. You have only ever been shown one of them. We switch on the other.

  1. Open Settings (the gear).
  2. In the search box at the top, type Linux. Click Linux development environment, then Turn on. (On some versions it lives under Advanced → Developers, or About ChromeOS → Developers. Same door, different hallway.)
  3. Username: type gillbert. Lowercase, no spaces.
  4. Disk size: it will suggest 10 GB. Do not accept that. Ask for 20 GB. The tools are large and one of them makes enormous temporary files while it thinks. Room is cheap. Regret is not.
  5. Let it install. It takes a few minutes. Use them to not narrate the progress bar.

When it finishes, a black window opens on its own. That is a terminal. That is the actual lab. Everything from here happens in there.

If that option is missing or greyed out

Then an administrator switched it off for the whole fleet, and there is a tiny building icon where the toggle should be. This is not something to defeat. It is a policy, not a puzzle. Use a personal Chromebook, or read Chapter 0.8 in the book for the three real alternatives. One of them is genuinely good.

STEP 03  /  HandlerInstall the kit

Empty terminal, meet the tools of the trade. Type these two lines into that black window. The first asks the machine to refresh its list of available software. The second installs everything the missions need.

$ sudo apt update
$ sudo apt install -y build-essential gdb binutils file xxd ltrace strace python3 unzip wget curl less

It will ask for the password you just set. Type it (the screen shows nothing while you do, that is normal, it is not broken), press Enter, and let it run.

Verify
Do not take its word for it. Ask each tool to prove it exists. If the machine prints a path for every one, you are done. If any line is blank, that tool did not install, and you run the line above again. 
$ for t in gcc gdb objdump strings xxd ltrace strace python3; do which $t; done
/usr/bin/gcc
/usr/bin/gdb
/usr/bin/objdump
...

The big one, Ghidra, is a separate and heavier install. The repo carries a script for it: once the lab is on the machine (next step), bash setup-ghidra.sh installs Ghidra and the Java it needs. It has a chapter in the book too (Part Zero). Leave it for now. The first several missions do not need it, and you learn more without it anyway.

STEP 04  /  HandlerPull down the lab

The missions, the book, and the checker all live in one repository. One command copies the whole thing onto this machine and, from then on, keeps it current.

Handler, swap the address

Replace the placeholder below with the real address of the repo you created. It is the green Code button on your GitHub page, the https:// line. If git is not installed yet: sudo apt install -y git.

$ git clone https://github.com/YOUR-NAME/dragons-eye.git ~/dragons-eye
$ cd ~/dragons-eye
$ ls
FIELD-MANUAL.md  MISSIONS.md  README.md  COLD-BOOT.html  book
checker  missions  scripts  setup-ghidra.sh  setup.sh  writeups
Verify
If ls shows those folders, the lab is on the machine. That is the last thing the handler has to do. Stand up.

Now that the repo is here: everything you typed by hand in Step 3 is also packaged as bash setup.sh, which installs the base kit and checks each tool for you. You did it by hand first so you would know what the button does. Next machine, or if anything ever looks missing, that one line rebuilds it.

STEP 05  /  AgentTake the keys

He is out of the chair. Now it is you.

First thing you do on your own machine is find out what it actually is. Ask it what kind of processor it has, because that decides which set of programs are yours:

$ uname -m
x86_64   # Intel/AMD -> you use missions/x86_64/
# or
aarch64  # ARM -> you use missions/arm64/

Now knock on the first door. It is locked. You do not have the key yet. That is the correct and intended state of the universe at this exact moment:

$ ./missions/x86_64/m01_helloghost
  Enter the password to lay the ghost to rest.
  password> # you have nothing. good. keep reading.

That prompt is the entire course in one line. Twelve times something asks you for a secret it is carrying inside itself, and twelve times you are going to reach in and take it instead of guessing.

The book teaches you the first reach in Chapter 1. Open it now:

$ # on the Chromebook, just double-click book/Gillbert-and-the-Dragons-Eye.html
$ # or from the ChromeOS Files app, it opens in the browser
The loop
Crack a door in the terminal. Prove it to the Eye: python3 checker/theeye.py 1. Collect the shard. Write down how you did it in writeups/. Next door. Twelve times. The README in this folder is your map for all of it.

One more thing, and then I am genuinely done talking.

Verify everything. Not because I said so. Because the entire discipline you are about to learn is one idea wearing twelve costumes: do not believe what a program claims. Look at what it does. The screen said "ACCESS DENIED." Fine. Was it telling the truth? You are going to spend a month finding out that programs lie constantly, mostly by accident, and that the only person who knows what a machine is really doing is the one who checked.

Somewhere out there is a version of you who closed this page at the first heading. He let someone else set up his machine and never learned what a terminal was. He takes every shortcut. He is going to be faster than you for about a week.

Then you are going to pass him and never see him again. Beat him the boring way. Do the reps.
